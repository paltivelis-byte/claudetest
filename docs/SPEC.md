# 青潮予報つき釣りカレンダー 仕様書（v0.1 ドラフト）

最終更新: 2026-10-01
ステータス: ドラフト（末尾「未決事項」の回答待ち）

---

## 1. 概要

釣り人向けのカレンダーアプリ。日ごとに **潮汐・天気・風** と **青潮の発生リスク** を一画面で確認でき、釣行の計画と記録に使う。

**解決したい課題**
- 青潮が出ると湾奥の魚が浅場から消えたり大量死したりして、釣りにならないことが多い。だが、その情報は自治体の速報・気象・潮汐などに散らばっていて、事前に判断しにくい。
- 「いつ・どこへ行くか」を決めるのに、潮回りと風と青潮リスクをまとめて見たい。

## 2. 背景：青潮とは（予報ロジックの前提）

| 項目 | 内容 |
|---|---|
| 現象 | 海底にたまった貧酸素水（硫化水素を含む）が表層に湧き上がる。硫化物が酸化して硫黄のコロイドになり、海面が乳白色〜青緑色に見える |
| 主な発生海域 | 東京湾奥（千葉県側：船橋・幕張・千葉港・浦安周辺）。ほかに三河湾・伊勢湾など |
| 時期 | 5〜11月。8〜10月がピーク |
| 発生条件 | ① 成層化（夏の水温差による上下の層の分かれ）　② 底層の貧酸素水塊（赤潮の残骸が分解されてできる）　③ **岸から沖へ吹く風（東京湾奥なら北〜北東風）が強く、長く続く** → 表層水が沖へ運ばれ、その代わりに底層水が湧き上がる |
| 釣りへの影響 | 発生域ではハゼ・アサリなどがへい死し、魚は避難するため釣果が大きく落ちる。発生域から外れた場所に魚が寄ることもある |

予報では ①②（下地があるか）と ③（引き金が引かれたか）を分けて評価する。

## 3. 対象ユーザー・利用シーン

- **主な対象**: 東京湾奥で陸っぱり・ボートをする釣り人（ハゼ、シーバス、クロダイ、アジなど）
- **シーン**
  1. 週末の釣行先を、数日前にカレンダーで比較して決める
  2. 前日〜当日朝に、青潮リスクと風を最終確認する
  3. 釣行後に釣果を記録し、そのときの条件（潮・風・青潮）と一緒にあとで振り返る

## 4. スコープ

## 5. 機能要件

### F-1 カレンダー（月表示）
- 各日のセルに次を表示する
  - 潮名（大潮・中潮・小潮・長潮・若潮）のアイコン
  - 青潮リスクレベルの色バッジ（§6.4）。予報期間外の未来日は表示しない
  - 釣行記録があればマーク
- 過去の日は、取得できれば **実際の発生情報**（自治体の青潮情報）を「発生」マークで表示する
- 表示するポイントを切り替えられる（デフォルトはお気に入りの先頭）

### F-2 日の詳細
- 潮位グラフ（24時間）、満潮・干潮の時刻と潮位
- 日の出・日の入り、月齢
- 時間ごとの天気・気温・風向・風速
- 青潮リスク: レベル、スコア、**根拠の内訳**（季節・底層の酸素・風）、信頼度
- その日の釣行記録の一覧・追加ボタン

### F-3 青潮予報
- ポイントごと・日ごとにリスクスコア（0〜100）とレベルを出す
- 更新タイミング: 1日4回（気象予報の更新に合わせて 05/11/17/23 時）
- 詳細は §6

### F-4 ポイント管理
- プリセット: 東京湾奥の代表的なポイント約20か所（例: 船橋三番瀬、幕張の浜、検見川の浜、浦安、若洲、豊洲、お台場、京浜運河など）
- ユーザー登録: 地図をタップして追加。名前と「沖の方角」を持つ（風の向きの評価に使う。プリセットは事前に設定、ユーザー登録分は海岸線から自動で推定し、手で直せる）
- お気に入り登録

### F-5 釣行記録
- 項目: 日付、開始/終了時刻、ポイント、魚種（複数）、匹数・サイズ、メモ、写真1枚、「青潮を見た」チェック
- 保存時に、その日の潮・風・青潮スコアのスナップショットを一緒に保存する（あとで振り返れるように）

### F-6 免責表示
- 予報画面に「予報は目安です。現地の状況を必ず確認してください」を常に表示する

## 6. 青潮予報ロジック（v0：ルールベース）

最初は説明しやすいルールベースのスコアで始め、過去の発生記録で閾値を調整する。パラメータはすべて設定ファイルで変えられるようにする。

### 6.1 入力データ

| 記号 | 指標 | 元データ |
|---|---|---|
| S | 季節係数（成層化の起きやすさ） | 月・表層水温 |
| H | 底層の貧酸素の度合い | 自治体の貧酸素水塊調査（底層の溶存酸素 DO）。取れない場合は季節の平年値で代用 |
| W | 引き金となる風の強さ | 気象予報の時間ごとの風向・風速（過去48時間の実測＋予報） |

### 6.2 各指標の計算（初期値、要調整）

- **S（0〜1）**: 6〜9月=1.0、5・10月=0.6、11月=0.3、それ以外=0.05
- **H（0〜1）**: 底層DO が 0.5 mg/L 以下=1.0、2.0 mg/L 以上=0、その間は直線で補間。データの日付が7日より古ければ、平年値との平均にする
- **W（0〜1）**: ポイントの「沖の方角」の単位ベクトルを **o** とし、時刻 t の風ベクトルを **v(t)** とする
  - 沖向き成分 `c(t) = max(0, v(t)・o)` [m/s]
  - 3 m/s 未満は無視し、評価日の朝6時までの直近36時間で `Σ (c(t) − 3) × 1h` を積算する
  - 積算値が 0 → W=0、60 m/s·h 以上 → W=1、その間は直線で補間
  - 例: 沖向き 8 m/s の風が12時間続くと、(8−3)×12 = 60 → W=1

### 6.3 スコア

```
score = round(100 × S × H × W^0.7)
```
- 掛け算にしているのは「下地（S・H）」と「引き金（W）」が両方そろわないと青潮は起きないため
- W に 0.7 乗をかけて、中くらいの風でもリスクが少し上がるようにしている

### 6.4 レベル

| レベル | スコア | 色 | 表示文言 |
|---|---|---|---|
| 0 低い | 0〜19 | 灰 | 青潮の心配は少ない |
| 1 注意 | 20〜49 | 黄 | 条件が一部そろっている |
| 2 警戒 | 50〜74 | 橙 | 発生の可能性あり |
| 3 高い | 75〜100 | 赤 | 発生の可能性が高い |

### 6.5 信頼度
- 当日・翌日=高、2〜3日先=中、4〜7日先=低（カレンダーでは薄い色で表示）
- H が平年値の代用なら信頼度を1段階下げる

### 6.6 検証
- 過去5年分以上の青潮発生記録（千葉県の公表情報）と気象の実測値でスコアを再計算（バックテスト）
- 目標: レベル2以上を「発生予測」としたとき、見逃し率 30% 以下・空振り率 50% 以下（初期目標。データを見て見直す）

## 7. データソース（候補）

| 用途 | 候補 | 備考 |
|---|---|---|
| 青潮の発生情報・貧酸素調査 | 千葉県水産総合研究センター「青潮情報」「貧酸素水塊速報」 | 取得方法（HTML/PDF）と利用条件の確認が必要 |
| 東京湾の環境データ | 東京湾環境情報センター、国交省の水質モニタリングポスト | 底層DOの連続観測がある地点を確認 |

| 日の出・日の入り | アプリ内で計算 | |

## 8. 画面構成

1. **カレンダー（ホーム）**: 上部でポイント切替、月グリッド、凡例
2. **日の詳細**: 潮位グラフ → 青潮リスクカード（内訳つき）→ 時間ごとの天気・風 → 釣行記録
3. **ポイント一覧/地図**: お気に入り、追加・編集
4. **釣行記録 一覧/入力**
5. **設定**: 単位、通知（将来）、データ出典・免責

## 10. 非機能要件

- **対応環境**: スマートフォン優先（PWA）。iOS Safari / Android Chrome の最新2バージョン
- **オフライン**: 直近に取得した7日分の予報と潮汐は電波がなくても見られる（磯や堤防は電波が弱いため）
- **性能**: カレンダーの初回表示 2秒以内（4G回線）
- **データ保存**: 釣行記録は MVP では端末内に保存。アカウント・クラウド同期は将来
- **可用性**: 外部データの取得に失敗したら、前回の値を「◯時点のデータ」と明記して表示する

## 11. 技術構成案

- **フロント**: TypeScript + React（Vite）、PWA（Service Worker でオフライン対応）、IndexedDB に保存
- **バックエンド**: 定期実行のバッチ（データ取得 → スコア計算 → JSON を静的に配信）
  - 例: GitHub Actions の cron、または Cloudflare Workers の Cron Triggers
  - MVP ではユーザー個別のデータをサーバーに置かないので、DB なしで始められる
- **予報ロジック**: 純粋関数のモジュールにして、単体テストとバックテストをしやすくする
