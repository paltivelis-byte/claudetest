# 青潮予報つき釣りカレンダー 仕様書（v0.2）

最終更新: 2026-10-01
ステータス: 方針確定（§14）。データ利用条件の確認待ち（§12）

---

## 1. 概要

釣り人向けのカレンダーアプリ。日ごとに **潮汐・天気・風** と **青潮の発生リスク** を一画面で確認でき、釣行の計画と記録に使う。

**解決したい課題**
- 青潮が出ると湾奥の魚が浅場から消えたり大量死したりして、釣りにならないことが多い。だが、その情報は自治体の速報・気象・潮汐などに散らばっていて、事前に判断しにくい。
- 「いつ・どこへ行くか」を決めるのに、潮回りと風と青潮リスクをまとめて見たい。

## 2. 背景：青潮とは（予報ロジックの前提）

| 項目 | 内容 |
|---|---|
| 現象 | 海底にたまった貧酸素水（硫化水素を含む）が表層に湧き上がる。硫化物が酸化して硫黄のコロイドになり、海面が乳白色〜青緑色に見える |
| 主な発生海域 | 東京湾奥（千葉県側：船橋・幕張・千葉港・浦安周辺）。ほかに三河湾・伊勢湾など |
| 時期 | 5〜11月。8〜10月がピーク |
| 発生条件 | ① 成層化（夏の水温差による上下の層の分かれ）　② 底層の貧酸素水塊（赤潮の残骸が分解されてできる）　③ **岸から沖へ吹く風（東京湾奥なら北〜北東風）が強く、長く続く** → 表層水が沖へ運ばれ、その代わりに底層水が湧き上がる |
| 釣りへの影響 | 発生域ではハゼ・アサリなどがへい死し、魚は避難するため釣果が大きく落ちる。発生域から外れた場所に魚が寄ることもある |

予報では ①②（下地があるか）と ③（引き金が引かれたか）を分けて評価する。

## 3. 対象ユーザー・利用シーン

- **主な対象**: 東京湾奥で陸っぱり・ボートをする釣り人（ハゼ、シーバス、クロダイ、アジなど）
- **公開範囲**: 一般公開する前提で作る（データの利用条件と法令は §12）
- **シーン**
  1. 週末の釣行先を、数日前にカレンダーで比較して決める
  2. 前日〜当日朝に、青潮リスクと風を最終確認する
  3. 釣行後に釣果を記録し、そのときの条件（潮・風・青潮）と一緒にあとで振り返る

## 5. 機能要件

### F-1 カレンダー（月表示）
- 各日のセルに次を表示する
  - 潮名（大潮・中潮・小潮・長潮・若潮）のアイコン
  - 青潮リスクレベルの色バッジ（§6.4）。予報期間外の未来日は表示しない
  - 釣行記録があればマーク
- 過去の日は、取得できれば **実際の発生情報**（自治体の青潮情報）を「発生」マークで表示する
- 表示するポイントを切り替えられる（デフォルトはお気に入りの先頭）

### F-2 日の詳細
- 潮位グラフ（24時間）、満潮・干潮の時刻と潮位
- 日の出・日の入り、月齢
- 気象庁の天気予報（天気・気温・降水確率・風の予報文）と、近くのアメダスの風の観測値（直近48時間）
- 青潮リスク: レベル、スコア、**根拠の内訳**（季節・底層の酸素・風）、信頼度
- その日の釣行記録の一覧・追加ボタン

### F-3 青潮予報
- ポイントごと・日ごとにリスクスコア（0〜100）とレベルを出す
- 更新タイミング: 1日4回（気象予報の更新に合わせて 05/11/17/23 時）
- 詳細は §6

### F-4 ポイント管理
- プリセット: 東京湾奥の代表的なポイント約20か所（例: 船橋三番瀬、幕張の浜、検見川の浜、江戸川放水路、浦安、若洲、豊洲、お台場、京浜運河など）
- 初回起動時のお気に入り（ユーザーがよく行く場所）。沖の方角は仮の値で、地図で確認して調整する

  | ポイント | 沖の方角（仮） | 潮汐の基準地点 | 備考 |
  |---|---|---|---|
  | 船橋（三番瀬・船橋港） | 南南西 200° | 東京 or 千葉 | 青潮の常発域 |
  | 検見川の浜 | 南西 225° | 千葉 | 青潮の常発域 |
  | 江戸川放水路（行徳・妙典） | 南 180° | 東京 | 河口から青潮が入り込む。ハゼ釣りへの影響が大きい |
  | 若洲海浜公園 | 南南東 160° | 東京 | 東京側。千葉側より発生は少ない |

- ユーザー登録: 地図をタップして追加。名前と「沖の方角」を持つ（風の向きの評価に使う。プリセットは事前に設定、ユーザー登録分は海岸線から自動で推定し、手で直せる）
- お気に入り登録

### F-5 釣行記録
- 項目: 日付、開始/終了時刻、ポイント、魚種（複数）、匹数・サイズ、メモ、写真1枚、「青潮を見た」チェック
- 保存時に、その日の潮・風・青潮スコアのスナップショットを一緒に保存する（あとで振り返れるように）

### F-6 免責表示
- 予測画面に「青潮リスクは独自の推定で、公的な予報・警報ではありません。現地の状況を必ず確認してください」を常に表示する
- データの出典（気象庁・千葉県・Open-Meteo など）を設定画面と各データの近くに表示する

## 6. 青潮予報ロジック（v0：ルールベース）

最初は説明しやすいルールベースのスコアで始め、過去の発生記録で閾値を調整する。パラメータはすべて設定ファイルで変えられるようにする。

### 6.1 入力データ

| 記号 | 指標 | 元データ |
|---|---|---|
| S | 季節係数（成層化の起きやすさ） | 月・表層水温 |
| H | 底層の貧酸素の度合い | 国交省の水質連続観測（モニタリングポスト）の底層の溶存酸素 DO。1時間ごと。取れない場合は千葉県の貧酸素水塊速報、それもなければ季節の平年値で代用 |
| W | 引き金となる風の強さ | 気象予報の時間ごとの風向・風速（過去48時間の実測＋予報） |

### 6.2 各指標の計算（初期値、要調整）

- **S（0〜1）**: 6〜9月=1.0、5・10月=0.6、11月=0.3、それ以外=0.05
- **H（0〜1）**: ポイントに紐づくモニタリングポストの、直近24時間の底層DO の平均を使う。0.5 mg/L 以下=1.0、2.0 mg/L 以上=0、その間は直線で補間。最新の観測が48時間より古ければ速報値か平年値との平均にする
  - 予測日（翌日以降）は直近の値を据え置く（底層の貧酸素は数日単位でしか変わらないため）
- **W（0〜1）**: ポイントの「沖の方角」の単位ベクトルを **o** とし、時刻 t の風ベクトルを **v(t)** とする
  - 沖向き成分 `c(t) = max(0, v(t)・o)` [m/s]
  - 3 m/s 未満は無視し、評価日の朝6時までの直近36時間で `Σ (c(t) − 3) × 1h` を積算する
  - 積算値が 0 → W=0、60 m/s·h 以上 → W=1、その間は直線で補間
  - 例: 沖向き 8 m/s の風が12時間続くと、(8−3)×12 = 60 → W=1

### 6.3 スコア

```
score = round(100 × S × H × W^0.7)
```
- 掛け算にしているのは「下地（S・H）」と「引き金（W）」が両方そろわないと青潮は起きないため
- W に 0.7 乗をかけて、中くらいの風でもリスクが少し上がるようにしている

### 6.4 レベル

| レベル | スコア | 色 | 表示文言 |
|---|---|---|---|
| 0 低い | 0〜19 | 灰 | 青潮の心配は少ない |
| 1 注意 | 20〜49 | 黄 | 条件が一部そろっている |
| 2 警戒 | 50〜74 | 橙 | 発生の可能性あり |
| 3 高い | 75〜100 | 赤 | 発生の可能性が高い |

### 6.5 信頼度
- 当日・翌日=高、2〜3日先=中、4〜7日先=低（カレンダーでは薄い色で表示）
- H が平年値の代用なら信頼度を1段階下げる

### 6.6 検証
- 過去5年分以上の青潮発生記録（千葉県の公表情報）と気象の実測値でスコアを再計算（バックテスト）
- 目標: レベル2以上を「発生予測」としたとき、見逃し率 30% 以下・空振り率 50% 以下（初期目標。データを見て見直す）

## 7. データソース

一般公開を前提に選んだ。利用条件の詳細と確認状況は §12。

| 用途 | 採用案 | 利用条件（調べた範囲） |
|---|---|---|
| 潮汐（満干潮・時間ごとの潮位） | 気象庁「潮位表」の天文潮位（東京・千葉）。年1回取り込む | 気象庁サイトの利用規約（公共データ利用規約 第1.0版、CC BY 4.0 と互換）。出典表示と、加工した場合はその旨の表示が必要 |
| 潮名・月齢・日の出入り | アプリ内で計算 | 制約なし |
| 天気（画面に表示する予報） | 気象庁の天気予報（千葉県北西部・東京地方）をそのまま表示 | 同上。気象庁の予報を手を加えずに伝えるだけなら予報業務許可は不要という理解（§12 で確認） |
| 風（画面に表示する実況） | 気象庁アメダス（船橋・千葉・江戸川臨海・羽田など）の観測値 | 同上 |
| 風（青潮スコアの計算に使う予報） | Open-Meteo（JMA MSM/GSM） | 無料版は非商用のみ → **収益化しないので無料版でよい**。CC BY 4.0 の出典表示が必要。上限は1日1万回（バッチで1日4回なら十分） |
| **底層の酸素（DO）＝ H の主な入力** | **国交省 関東地方整備局の水質連続観測（東京湾環境情報センターで公開）**。浦安沖・検見川沖・千葉港口第一号ブイ・川崎人工島、千葉灯標。海面から海底まで1mごとに毎正時に観測 | 国の機関のサイトなので政府標準の利用規約（出典表示で二次利用可）と思われるが、サイト利用規約の原文を要確認 |
| 底層の酸素（補助） | 千葉県水産総合研究センター「貧酸素水塊速報」 | 掲載物は無断転用不可。MVP では使わない（湾全体の分布を見たくなったら県に相談） |
| 過去の青潮の発生記録（スコアの検証用） | 千葉県環境研究センター 年報「東京湾の青潮発生状況」（年度ごと、発生日・範囲） | 検証に使うだけで、アプリには再掲しない。発生日という事実の利用なので許可は不要と考えるが、出典は仕様書・README に書く |
| 直近の青潮の発生（カレンダーの「発生」マーク） | 千葉市「市内における直近の赤潮・青潮の発生状況」 | 市サイトの利用条件を要確認。確認できるまでは「発生」マークを出さず、リンクだけ置く |

**ポイントとモニタリングポストの対応（仮）**

| ポイント | 使うモニタリングポスト |
|---|---|
| 船橋（三番瀬・船橋港） | 浦安沖・検見川沖の平均 |
| 検見川の浜 | 検見川沖 |
| 江戸川放水路 | 浦安沖 |
| 若洲海浜公園 | 浦安沖 |

モニタリングポストでは海上の風も観測しているので、アメダスの補助として表示に使える（観測値なので予報業務許可とは無関係）。

**方針**: 画面に出す天気・風は気象庁の発表と観測値だけにする。数値予報モデルの風は青潮スコアの計算にだけ使い、そのまま「風の予報」として表示しない（§12 の確認が済むまで）。
なお §12 は検索で調べた範囲の整理で、各サイトの利用規約の原文はまだ直接読めていない。公開前に原文で確かめる。

## 8. 画面構成

1. **カレンダー（ホーム）**: 上部でポイント切替、月グリッド、凡例
2. **日の詳細**: 潮位グラフ → 青潮リスクカード（内訳つき）→ 天気予報・風の観測値 → 釣行記録
3. **ポイント一覧/地図**: お気に入り、追加・編集
4. **釣行記録 一覧/入力**
5. **設定**: 単位、釣行記録の書き出し・読み込み、データ出典・利用規約・プライバシーポリシー

## 10. 非機能要件

- **対応環境**: スマートフォン優先（PWA）。iOS Safari / Android Chrome の最新2バージョン
- **オフライン**: 直近に取得した7日分の予報と潮汐は電波がなくても見られる（磯や堤防は電波が弱いため）
- **性能**: カレンダーの初回表示 2秒以内（4G回線）
- **データ保存**: 釣行記録は端末内（IndexedDB）に保存する。機種変更やブラウザのデータ消去に備えて、JSON ファイルでの書き出し・読み込みを付ける
- **プライバシー**: 釣行記録や位置情報はサーバーに送らない。アクセス解析を入れる場合も個人を特定しない形にする
- **可用性**: 外部データの取得に失敗したら、前回の値を「◯時点のデータ」と明記して表示する

## 11. 技術構成案

- **フロント**: TypeScript + React（Vite）、PWA（Service Worker でオフライン対応）、IndexedDB に保存
- **バックエンド**: 定期実行のバッチ（データ取得 → スコア計算 → JSON を静的に配信）
  - 例: GitHub Actions の cron、または Cloudflare Workers の Cron Triggers
  - MVP ではユーザー個別のデータをサーバーに置かないので、DB なしで始められる
- **予報ロジック**: 純粋関数のモジュールにして、単体テストとバックテストをしやすくする

## 12. 一般公開に向けた法令・利用条件

### 12.1 気象業務法（予報業務許可）
- 気象業務法 第17条で、気象庁以外が予報業務をするのに許可が要るのは「**気象、地象、津波、高潮、波浪又は洪水**」の予報。
- 青潮は「水象」（気象に密接に関連する海洋の現象）にあたると考えられるが、第17条の列挙には入っていない。そのため**青潮リスクの予測を出すこと自体は許可不要の可能性が高い**。
- ただし次は許可が要る、または判断が分かれるので避ける・確認する:
  - アプリ独自の天気・風の予報を表示する（「気象」の予報になる）→ **気象庁の予報をそのまま表示**する
  - 数値予報モデルの値をポイントごとの風の予報として表示する → MVP では表示しない
  - 潮位の予想を独自に出す（「高潮」の予報要素に潮位がある）→ 気象庁の天文潮位表をそのまま使う
- **TODO**: 公開前に気象庁（予報業務許可の担当窓口）へ「青潮リスク予測アプリ」の扱いを問い合わせ、回答を記録する。

### 12.2 データの利用条件
- **気象庁**: 公共データ利用規約（CC BY 4.0 互換）。設定画面とデータを表示する画面に出典を書く。例「出典：気象庁ホームページ（潮位表）を加工して作成」
- **国交省（東京湾環境情報センター）**: H の主な入力。サイト利用規約の原文を確認し、出典の書き方を決める。
- **千葉県**: サイトの掲載物は無断転用不可。MVP では県のデータを取り込まない（青潮の年報は検証にだけ使う）。
- **千葉市**: 直近の青潮発生状況の表示に使えるか、利用条件を確認する。
- **Open-Meteo**: 収益化しないので無料版を使う。CC BY 4.0 の出典表示をする。
- 取得はサーバー側のバッチで1日4回に限り、ユーザーの端末から各サイトへ直接アクセスさせない（相手サーバーへの負荷を抑える）。

### 12.3 免責・表示
- 利用規約とプライバシーポリシーのページを用意する
- 「青潮リスクは独自の推定で、公的な予報・警報ではありません。現地の状況を必ず確認してください」を予測画面に常に表示する（F-6 を強化）
